# VidLink 配额说明（用户版）

本文面向所有使用 VidLink API 的用户，说明每次调用消耗多少配额，以及如何查看自己的用量。

---

## 0. 先用起来：公共 Key `vl_public`

不想注册也能试：带上公共 Key 就能用，**不需要申请**。

```bash
curl -H "X-API-Key: vl_public" \
  'http://127.0.0.1:8080/v1/links?url=https://www.bilibili.com/video/BV1xxxx'
```

- 额度是**每个 IP 每天 25 配额**（和下面第 3 节的系数同一套口径；代理 0.5 配额/MiB，
  所以 25 配额大约能下 50 MB）；
- 用完了返回 `429`，提示你去申请独立 Key；额度每天零点自动重置；
- 公共 Key **看不到账单**（它是共享账号，流水混着所有访客的调用）；
  想知道自己每一笔消耗，请申请独立 Key。

## 1. 什么是配额？

配额是你可以调用 API 的额度上限，由管理员分配。**它不是钱、不是余额、不与任何支付挂钩。**
你可以把它理解为"可用的调用额度"。

**配额用完怎么办？** 联系管理员。管理员可以给你增加配额，或者调低你的倍率。

---

## 2. 消耗公式

```
一次调用的消耗 = 端点系数 × 条数 × 你的账号倍率
```

- **端点系数**：不同的接口消耗不同（见第 3 节）。
- **条数**：只有批量接口大于 1，其余接口固定为 1。
- **账号倍率**：你的账号专属倍率，默认 1.0（见第 5 节）。

---

## 3. 各接口消耗一览

| 接口 | 用途 | 抖音 | 其他平台 |
| --- | --- | --- | --- |
| `GET /v1/info` | 只看元信息，不含直链 | 0.75 | 0.5 |
| `GET /v1/links` | 只取直链 | 1.1 | 1.0 |
| `GET /v1/detail` | 元信息 + 直链 + 字幕/图集 | 1.5 | 1.2 |
| `POST /v1/batch/links` | 批量取直链（**每条**） | 不支持 | 0.75 |
| `GET /v1/proxy` | 媒体代理（下载/播放直链） | **0.5 / MiB** | **0.5 / MiB** |

"其他平台"包括：哔哩哔哩、快手、小红书。

**媒体代理是按体积算的**：`消耗 = 传输体积(MiB) × 0.5 × 你的账号倍率`，不区分平台、
也不区分账号类型（所有人同一个价）。例如走代理下载一个 70 MB 的视频 = 约 35 配额
（倍率 1.0 时），1 GB ≈ 512 配额；只请求 1 KB 的那一小段（播放器拖进度条）≈ 0.0005 配额。所以**能直连就不要走代理**：直连不消耗配额，
代理只是在 CDN 要求 Referer/UA 时的兜底通道。

**怎么选最省配额？**

- 只想看有哪些档位 → 调 `info`（最便宜）
- 确定要直链 → 直接调 `links`，或调 `detail`
- 需要元信息 + 直链 → 调 `detail`（打包，比分开调便宜）
- 需要多条直链 → 调 `batch_links`（每条便宜 25%，5~20 条）

> **注意：抖音不支持批量接口。**
> 抖音按 IP 维度限流，批量会瞬间打出多个请求，容易被判定为异常流量。
> 请逐条调 `GET /v1/links`。

---

## 4. 什么情况不扣配额？

- 上游超时
- 内容不存在
- 被限流
- 参数错误
- 批量接口里失败的条目

简单说：**只有真正成功返回结果才扣。** 上游抖动不是你的问题。

## 4.5 每日签到（自己领配额）

如果管理员给你的账号开了签到，你可以每天自己领一次配额，不用等人：

```bash
curl -X POST -H "X-API-Key: $KEY" http://127.0.0.1:8080/v1/checkin
# {"granted":25,"balance":125,"message":"签到成功：+25 配额，当前剩余 125",...}
```

- **只有签到会给你加配额**：服务不会"每天第一次调用时自动补"，也不会因为你
  解析过一次就顺手加——不加就是不加，想要就签一次；
- **每天一次**（本地时间零点后可再签）；当天第二次返回
  `already_checked_in: true`，不会重复加；
- 余额达到管理员设的「停止增加界限」时不再增加（`at_cap: true`），
  而且**不占用当天的机会**——花掉一些之后当天还能签；
- 签到本身不消耗配额；每次签到都会在账单里留一条 `管理员增加` 的记录，
  说明写的是「每日签到 +25 → 125（上限 200）」；
- 没开签到的账号调它会返回 `400`，让管理员在账号上设一下「每日签到额度」即可。

网页端在解析页的「账户与用量」里点「每日签到领配额」按钮就行；
想用脚本判断"这个账号能不能签到"，看 `GET /v1/usage` 的 `checkin.enabled`。

## 5. 账号倍率

管理员可以给你的账号设置倍率，影响你每次消耗的多少。

| 倍率 | 效果 |
| --- | --- |
| `0` | 不消耗配额（**仍记录调用次数**） |
| `0.5` | 消耗减半 |
| `1.0` | 标准（默认） |
| `2.0` | 消耗翻倍 |

倍率**只针对你的账号**，不影响其他用户。如果你觉得消耗太快，可以联系管理员调低倍率。

## 5.5 怎么查"这笔消耗是怎么来的"？

`GET /v1/usage` 只告诉你"现在剩多少、累计用了多少"。想知道**每一笔的明细**
（哪次解析扣的、管理员什么时候给你加/减过），用配额流水：

```bash
curl -H "X-API-Key: $KEY" 'http://127.0.0.1:8080/v1/ledger?limit=20'
```

返回里每一条都带：时间、类型（使用 / 管理员增加 / 管理员减少 / 管理员设置 /
创建 / 删除）、变化量（消耗是负数）、变化后余额、以及一句说明
（例如 `detail/bilibili ×1`、`proxy 66.53 MiB（按体积）`、`管理员增加 100 配额`）。
`totals` 是分类汇总，**是全量口径**；`entries` 只保留最近若干条。

网页端在解析页的「**配额流水（账单）**」一栏，填好 Key 就能看，还能按类型筛。

**这个接口不消耗配额**——对账本身不该收费。

## 6. 如何查看自己的用量？

| 接口 | 说明 |
| --- | --- |
| `GET /v1/usage` | 查看剩余配额、已用配额、累计调用次数、你的倍率 |
| `GET /v1/platforms` | 查看支持的平台及各平台系数（**不消耗配额**） |

每次调用的响应头里也会带上：

- `X-Quota-Consumed`：本次消耗了多少
- `X-Quota-Remaining`：还剩多少

## 7. 算例

| 场景 | 消耗 |
| --- | --- |
| 快手取直链 | **1.0** |
| 抖音取直链 | **1.1** |
| 抖音看元信息 | **0.75** |
| 抖音元信息 + 直链（分开调） | 0.75 + 1.1 = **1.85** |
| 抖音元信息 + 直链（调 `detail`） | **1.5**（更划算） |
| 批量 10 条快手 | **7.5** |
| 批量 10 条快手，3 条失败 | 0.75 × 7 = **5.25** |
| 抖音 `detail`，倍率 0.5 | **0.75** |

## 8. 常见问题

**Q：配额用完了会怎样？**
A：返回 `429`，提示配额不足。联系管理员增加配额。

**Q：为什么抖音消耗更多？**
A：抖音的元信息和直链走的是**同一条**上游请求，而它在 IP 维度限流、风控更严，
所以成本更高，系数整体上浮。

**Q：为什么抖音不支持批量？**
A：批量会瞬间打出多个请求，触发抖音的 IP 限流，导致整台服务器在一段时间内
无法正常解析。为了保护服务质量，抖音必须逐条调。

**Q：结算失败会影响我拿到的结果吗？**
A：不会。你已经拿到的解析结果不会因为配额记账问题被撤回（服务端会记日志排查）。

**Q：怎么知道我的倍率是多少？**
A：调 `GET /v1/usage` 就能看到。

**Q：直链拿到后为什么下载/播放失败？**
A：多半是没带 `headers`（平台 CDN 有 Referer 防盗链），见
[`API.md`](API.md#7-排障)。B 站返回 `audio_url` 时需要先混流。
